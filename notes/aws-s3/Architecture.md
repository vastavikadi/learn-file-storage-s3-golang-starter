# S3 Architecture Fundamentals

> S3 is a simple object storage service where files (objects) are stored in buckets with unique keys. Bucket names are globally unique across all AWS accounts.

## Prerequisites
- Basic understanding of DNS and URLs

## Key Concepts

### S3 Object Storage Model

S3 stores data as objects in buckets. Each object requires exactly two identifiers: the bucket name and the object key. Think of it as a giant key-value store where the bucket is the namespace and the key is the path within that namespace.

**Examples:**
- File A → Bucket B → Key C

> ⚠️ **Gotchas:**
> - Bucket names must be globally unique across ALL AWS accounts, not just your own

### Bucket Naming Constraints

Bucket names form part of the S3 URL (e.g., https://bucket-name.s3.region.amazonaws.com/key), so they must be globally unique. This is why you cannot create a bucket named 'bootdev' if someone else already owns it.

**Examples:**
- Company prefix pattern: bootdev-user-images, bootdev-video-assets, acme-customer-uploads

> ⚠️ **Gotchas:**
> - No two AWS accounts can have the same bucket name
> - Bucket names are DNS-compliant (lowercase, no underscores, 3-63 chars)

### Object Key

The object key is the full path/filename within the bucket. It can include 'folders' using forward slashes (e.g., 'images/2024/photo.jpg'), but S3 is flat — there are no real directories, just keys with prefixes.

**Examples:**
- Key examples: 'profile.png', 'uploads/user-123/avatar.jpg', 'videos/intro.mp4'

> ⚠️ **Gotchas:**
> - Keys are case-sensitive
> - Leading slash in key is optional but changes the key (e.g., '/file.txt' ≠ 'file.txt')

## Mental Models

### 💡 S3 as a Global Key-Value Store

Think of S3 as one massive hash map: bucket name = top-level namespace, object key = key within that namespace. The value is the file content + metadata.

## Code Examples

### S3 Object URL Structure

The bucket name appears in the hostname, which is why it must be globally unique.

```text
https://{bucket-name}.s3.{region}.amazonaws.com/{object-key}
```

## Common Mistakes

- ❌ Assuming bucket names only need to be unique within your AWS account
- ❌ Trying to use underscores in bucket names (not allowed for DNS compatibility)
- ❌ Treating S3 keys like filesystem paths with real directories

## Key Takeaways

- ✅ S3 access requires only two things: bucket name + object key
- ✅ Bucket names are globally unique across all AWS — use a company/project prefix
- ✅ S3 is flat; 'folders' are just key prefixes with forward slashes

## Practice Questions

**Q1:** Why must S3 bucket names be globally unique?

<details><summary>Answer</summary>

Because bucket names are part of the DNS hostname used to access objects (e.g., bucket-name.s3.region.amazonaws.com), and DNS names must be globally unique.

</details>

**Q2:** What two pieces of information do you need to retrieve an object from S3?

<details><summary>Answer</summary>

The bucket name and the object key.

</details>
